## 1. Назначение и двухстендовая архитектура

Формат `.fsspack` разработан для безопасного, воспроизводимого и изолированного обмена кристаллографическими данными между двумя функциональными контурами Fedorov Symmetry Stand (FSS V2):

1. **Стенд № 1 — Reference Stand (Справочно-математический контур):**
   * Хранит эталонную кристаллографическую базу и строгий неизменяемый стандартный каталог из **8 групп** (`REGISTERED_SETTING_IDS`: `P1`, `P-1`, `P2`, `P21`, `C2`, `Cc`, `P21/c`, `P212121`).
   * Неизменяем при любых внешних операциях.
   * Экспортирует группы в формате `.fsspack`.

2. **Стенд № 2 — Experimental Lab (Экспериментальная лаборатория):**
   * Изолированный исследовательский контур.
   * Принимает пакеты `.fsspack` через независимый входной шлюз (**Gatekeeper**).
   * Помещает импортированные группы в **Local Vault** в неактивном состоянии (`isActiveInClassifier = false`).
   * Активация групп в экспериментальном классификаторе требует явного действия пользователя/агента (`activateSetting`), исключая непреднамеренное засорение классификатора.
   * Не имеет прав на обратную мутацию Стенда № 1.

## 2. Представление математических данных

### 2.1. Запрет чисел с плавающей точкой
Любые вычисления симметрии, сравнения трансляций, таблицы Кэли, проверка замкнутости и хеширование полезной нагрузки проводятся строго на точных математических типах:
* Матрицы вращения/инверсии: $\mathbf{W} \in \mathrm{GL}(3, \mathbb{Z})$, целочисленные массивы $3 \times 3$.
* Дробные трансляции: точные рациональные дроби `{ "n": int, "d": int }`, где $d > 0$, приведенные к взаимно простым числам и редуцированные по модулю 1 на интервал $[0, 1)$ через класс `ExactRational` с использованием `BigInt`.
* Вычисление определителей и матричных произведений выполняется без округлений.

### 2.2. Аффинные операторы
Операция симметрии задаётся расширенным оператором:
$$g(\mathbf{x}) = \mathbf{W}\mathbf{x} + \mathbf{w} \pmod{\mathbb{Z}^3}$$

Композиция двух операций $(W_1, w_1) \circ (W_2, w_2)$:
$$W_{12} = W_1 W_2, \quad w_{12} = (W_1 w_2 + w_1) \bmod 1$$

Требования к матрицам:
* Унимодулярность и ортогональность: $\mathbf{W}^\top \mathbf{W} = \mathbf{I}_3$.
* Определитель $\det(\mathbf{W}) \in \{+1, -1\}$ (допускаются как собственные вращения $+1$, так и несобственные вращения, отражения и инверсия $-1$).

## 3. Целостность пакета и каноническая сериализация (RFC 8785)

Для гарантии независимости контрольных сумм от среды выполнения (V8, JavaScript, Python, Rust) хеширование полезной нагрузки подчиняется стандарту **RFC 8785 (JSON Canonicalization Scheme — JCS)**:

1. **Ключи объектов:** строго сортируются по возрастанию кодовых точек UTF-16 на каждом уровне вложенности.
2. **Числа:** форматируются согласно стандарту ECMAScript/JCS, значение `-0` нормализуется в `0`.
3. **Строки:** минимальное экранирование (`\"`, `\\`, ASCII control chars `\u0000`..`\u001f`).
4. **Пробельные символы:** незначимые пробелы и переносы строк между токенами отсутствуют.
5. **Контрольная сумма:** вычисляется алгоритмом `SHA-256` в шестнадцатеричной кодировке (64 символа в нижнем регистре).
6. **Область хеширования:** поле `manifest.payload_sha256` вычисляется строго от JCS-представления объекта `payload`. Сам блок `manifest` исключается из хеширования для разрыва циклической зависимости.

*Примечание:* Контрольная сумма SHA-256 обеспечивает **контроль целостности** (integrity check) и не является асимметричной цифровой подписью.

## 5. Пайплайн проверок Gatekeeper и таблица кодов ошибок

Шлюз Gatekeeper реализует принцип нулевого доверия к заявлениям отправителя (`sender_attestation`) и выполняет 9 обязательных валидаций:

| Код проверки | Название проверки | Критерий валидации | Код ошибки при сбое |
|---|---|---|---|
| **GK-01** | Schema & Syntax | Валидация структуры по схеме V1.0, запрет нерегламентированных полей | `ERR_SCHEMA_VIOLATION` |
| **GK-02** | Kernel Compatibility | Проверка диапазона совместимости semver (текущее ядро >= требуемого) | `ERR_KERNEL_INCOMPATIBLE` |
| **GK-03** | Payload Integrity | Повторный расчёт SHA-256 от JCS(payload), сравнение с манифестом | `ERR_PAYLOAD_INTEGRITY_COMPROMISED` |
| **GK-04** | Matrix Validity | $\det(\mathbf{W}) \in \{+1, -1\}$, целочисленность, $\mathbf{W}^\top \mathbf{W} = \mathbf{I}_3$ | `ERR_INVALID_ROTATION_MATRIX` |
| **GK-05** | Identity Element | Наличие ровно одного единичного элемента $(I_3, \mathbf{0} \bmod 1)$ | `ERR_IDENTITY_ELEMENT_MISSING` |
| **GK-06** | Group Closure | Замкнутость множества операций относительно аффинной композиции $\bmod \mathbb{Z}^3$ | `ERR_GROUP_CLOSURE_FAILED` |
| **GK-07** | Inverses Existence | Существование двустороннего обратного элемента для каждой операции | `ERR_INVERSE_ELEMENT_MISSING` |
| **GK-08** | Chirality & Screw Guard | Для энантиоморфов: сверка шага винтовой оси с заявленным номером группы | `ERR_CHIRALITY_MISMATCH` |
| **GK-09** | Workspace Conflict | Проверка уникальности идентификатора настройки в Local Vault | `ERR_WORKSPACE_ID_CONFLICT` |

## 6. Дискриминация энантиоморфов: SG 76 ($P4_1$) vs SG 78 ($P4_3$)

Группы $P4_1$ и $P4_3$ изоморфны по точечной группе $4$ ($C_4$), имеют тетрагональную сингонию и порядок 4. Простое совпадение точечных групп или матриц поворота **не доказывает** идентичность пространственной группы.

Дискриминатор Gatekeeper опирается на геометрический инвариант:
1. Винтовая ось 4-го порядка направлена вдоль $[0, 0, 1]$ с матрицей поворота:
   $$\mathbf{W}_{4+} = \begin{pmatrix} 0 & -1 & 0 \\ 1 & 0 & 0 \\ 0 & 0 & 1 \end{pmatrix}$$
2. При произвольном сдвиге начала координат $\boldsymbol{\Delta} = [x_0, y_0, z_0]^\top$:
   $$\mathbf{w}' = \mathbf{w} + (\mathbf{I} - \mathbf{W})\boldsymbol{\Delta}$$
   Поскольку третья строка матрицы $(\mathbf{I} - \mathbf{W}_{4+})$ тождественно равна $[0, 0, 0]$, $z$-компонента трансляции $w_z$ **абсолютно инвариантна** к выбору начала координат:
   $$w_z' \equiv w_z \pmod 1$$
3. Для $P4_1$ (SG 76): $w_z \equiv +1/4 \pmod 1$.
4. Для $P4_3$ (SG 78): $w_z \equiv +3/4 \pmod 1$.
5. Попытка импорта операций $P4_3$ под номером 76 немедленно прерывается ошибкой `ERR_CHIRALITY_MISMATCH`.

## 7. Статусы доступности классификатора

При импорте записи в FSS V2 определяется статус доступности:
* `DEFAULT_CATALOG`: Запись входит в 8 базовых настроек Стенда № 1.
* `EXTENDED_ONLY`: Запись зарегистрирована в справочном реестре, но изолирована от стандартного каталога (например, P41 в Stand 1).
* `NOT_IN_CATALOG`: Внешняя или изолированная запись, отсутствующая в реестре Стенда № 1.

Эти статусы обозначают конфигурационную доступность классификатору, а не математическую корректность.
